# 仓库组织说明

## 目标

本仓库不作为可部署产品，只用于验证 git 操作：新增、修改、删除、暂存、提交、差异对比在多种文件类型上的表现。

## 组织原则

1. **一语言一目录** — 目录名与语言一致，便于按类型筛选差异（`git diff -- python/`）。
2. **最小可运行示例** — 每个程序既有正常路径也有可预期错误路径，错误必须被捕获并记录，用于验证日志类改动在 diff 中的可读性。
3. **配置与数据分离** — `config/` 只放应用配置，`data/` 只放样例数据，避免同一文件承担两种职责。
4. **接口契约独立** — `proto/` 与 `api/` 存放跨端契约，改动频率与实现代码不同，便于单独评审。
5. **零外部依赖** — 示例只用各语言标准库，任何机器可直接运行，不因缺少依赖导致校验失败。

## 文件类型覆盖

| 类别 | 文件 |
|------|------|
| 编译型语言 | `java/` `kotlin/` `rust/` `go/` `c/` `cpp/` `csharp/` `swift/` `dart/` |
| 解释型语言 | `python/` `ruby/` `php/` `shell/` `lua/` `r/` |
| 前端生态 | `src/typescript/` `src/javascript/` `src/react/` `src/vue/` `src/svelte/` `web/` |
| 声明式/脚本 | `sql/` |
| 数据与配置 | `data/` `config/` |
| 接口契约 | `proto/` `api/` |
| 文档 | `README.md` `docs/` |

## 改动约定

- 修改示例逻辑时同步更新其上方注释，避免注释过期
- 新增语言示例时同步更新 `README.md` 的目录结构表与 `data/sample.json` 的语言清单
- 不提交编译产物与 IDE 配置（见 `.gitignore`）
